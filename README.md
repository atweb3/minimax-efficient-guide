# 📘 高性价比使用 MiniMax 通用攻略（2026-04-12 修订版）

> 适用于：自动化搭建、AI产品开发、代码生成、配置编写等技术任务

**核心原则**  
把 MiniMax 当作 **“能按规格输出代码的生成器”**，而不是“能替你调试和诊断的工程师”。

**本次修订新增的关键教训**（来自真实项目“AI Builders Digest”）：
- ❌ 不要让它猜测“为什么收不到消息”，它会编造“仓库被删除”“定时任务禁用”等虚假结论。
- ❌ 不要让它建议“删除 state 文件”来解决问题，它常搞错根因。
- ✅ 只让它做：**根据你提供的明确信息（数据源结构、错误日志）生成或修复代码**。

---

## 一、五步高效工作流（修订版）

### 第1步：你自己做最小化验证（不要用 AI 做）
- 手动测试 webhook（`curl`）、查看 Actions 日志、打印数据源结构。
- **目的**：确认问题范围，避免 AI 漫无目的地猜测。

### 第2步：将问题拆解成“单一、可描述的代码缺陷”
- 错误示例：“飞书收不到消息，帮我看看”。→ AI 会瞎猜。
- 正确示例：“我的数据源结构是 `{x:[{tweets:[]}]}`，但脚本用 `data.items` 解析，导致 `items` 为空。请修正解析逻辑。”

### 第3步：要求只输出代码，禁止输出任何解释
- 指令模板：
  > “请只输出修复后的完整 `index.js` 文件内容。不要输出表格、分析、建议、问候语。不要要求我提供 Token。”

### 第4步：自己部署、测试、反馈
- 将 AI 输出的代码复制到仓库，手动触发运行。
- 如果失败，将新的错误日志贴给 AI，要求“只修改第 X 行”。

### 第5步：拒绝 AI 的任何“操作请求”
- 若 AI 要求提供 GitHub Token、调用 API、或让你“点一下某处”，**直接拒绝**并重新明确指令：“只输出代码”。

## 二、积分控制技巧表（新增“危险信号”）

| 场景 | ✅ 推荐做法 | ❌ 危险信号（立即停止） |
|------|-------------|------------------------|
| 初次诊断 | 自己用 `curl`/日志定位问题范围 | AI 输出“仓库可能不存在”“定时任务可能被禁用”等无依据猜测 |
| 生成代码 | 要求“直接给完整文件，不要解释” | AI 输出长篇诊断报告或表格 |
| 调试错误 | 贴出完整错误日志，要求“只修改必要行” | AI 建议删除 `state-feed.json` 或做空提交 |
| 验证成功 | 手动触发，不看 AI 的“成功报告” | AI 声称“我已修复成功，请查看”但无代码输出 |

**积分止损线**：如果 AI 连续 2 轮输出无关内容或错误建议，立即终止对话，换用更精确的指令或换一个 AI。

## 三、实战案例：本次项目中的错误与正确做法

| 你的操作 | AI 反应 | 评价 | 正确做法 |
|----------|---------|------|----------|
| “飞书收不到消息” | AI 猜测仓库被删除、定时任务禁用 | ❌ 浪费积分 | 先手动 `curl` 测试 webhook，确认连通性 |
| “手动触发成功但没收到” | AI 建议删除 `state-feed.json` | ❌ 错误根因 | 打印数据源结构，发现解析错误 |
| 提供数据源 JSON 示例 | AI 输出修复后的解析代码 | ✅ 有效 | 继续用此模式 |
| 要求“只输出修复后的 `index.cjs`” | AI 直接给出代码 | ✅ 高性价比 | 保留此模板 |

**结论**：AI 最擅长的是“根据明确的规格改代码”，最不擅长的是“诊断未知问题”。

## 四、推荐指令模板（复制即用）

### 模板 1：修复已知的代码缺陷
```text
【任务】修复以下代码问题。

【错误现象】（粘贴 Actions 日志中的关键报错或缺失输出）

【数据源结构】（如果涉及，粘贴 JSON 示例）
{ "x": [{ "tweets": [{"id":"1","text":"..."}] }] }

【当前脚本片段】（粘贴需要修改的函数）

【要求】
只输出修复后的完整文件内容（例如 `index.js`）。不要输出任何解释、表格或建议。
```

### 模板 2：生成新功能
```text
【任务】根据以下需求生成代码。

【需求描述】
写一个 Node.js 脚本，完成：
1. 读取 JSON 文件 `data.json`
2. 提取其中 `items` 数组
3. 发送到飞书 webhook（环境变量 `FEISHU_WEBHOOK_URL`）

【要求】
只输出完整的 `.js` 文件内容，不要多余文字。
```

## 五、适用场景与禁用场景

| 适合使用 MiniMax | 不适合使用 MiniMax |
|----------------|-------------------|
| 生成样板代码（CRUD、脚本、配置文件） | 诊断“为什么我的系统不工作” |
| 根据已知数据结构改写解析逻辑 | 排查网络、权限、环境变量问题 |
| 将一种语言代码翻译成另一种 | 操作你的 GitHub 仓库或云服务 |
| 生成单元测试用例 | 提供项目架构建议（容易过时或错误） |

## 六、总结（更新版）

> **MiniMax 是你的“代码打印机”，而不是“技术合伙人”。**  
> 你提供精确的输入（错误日志 + 数据示例 + 当前代码），它输出精准的修复代码。  
> **不要为任何“描述性报告”或“操作建议”支付积分。**

**每次提问前问自己：**  
👉 “我能不能在 2 分钟内手动验证问题范围？”  
👉 “我能不能提供数据源的实际 JSON 示例？”  
👉 “我要求的产出是不是一个可以直接复制的代码文件？”

如果三个答案都是“是”，再提交任务。否则，先自己做基础排查。
